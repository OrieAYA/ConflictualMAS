# 多ロボット経路計画デモ（DbVNS に時空間制約を統合）

複数のロボットが、それぞれ順番に複数の目標地点（一部は「この時刻以降
でないと使えない」という制約つき）を巡回しながら、**互いに衝突しない
経路**を計算する様子を、高校生向けにわかりやすく見せるデモです。

出力形態は2つ：
- **MP4動画**（`video_export.py`）：そのまま授業で再生するだけでOK。
  一番手軽で、おすすめです。
- **対話的なGUI**（`main.py` / `gui.py`）：その場で1ステップずつボタンを
  押しながら確認したいとき用（Tkinter使用）。

## 動画を作る

```bash
python3 video_export.py 出力ファイル名.mp4
```

Python 3 と matplotlib、ffmpeg が必要です（`pip install matplotlib`、
`sudo apt install ffmpeg`）。日本語表示には Noto Sans CJK JP のような
日本語フォントが必要です（`sudo apt install fonts-noto-cjk`）。

動画は次の順番で構成されています：

1. **導入**：タイトルカード
2. **計画フェーズ**：ロボットごとに、DbVNSがどうやって経路を探索するか
   を1イベントずつ再生（探索中のマス・禁止されたマス・完成した経路）
3. **切り替えカード**：「計画完了：全ロボットの経路が確定しました」
4. **シミュレーションフェーズ**：全ロボットが実際に同時に動く様子を、
   滑らかな補間つきでアニメーション。**計画済みの経路を薄い線で常に
   表示したまま**動かすので、「今どこを進んでいるか」がひと目で
   わかります。大きな時刻カウンター付き。
5. **終了カード**

## GUIで動かす（その場で操作したい場合）

```bash
python3 main.py
```

「次のステップ」ボタンで1手ずつ、「自動再生」で連続再生、
「シミュレーション開始」で実際の同時移動を見られます。

## 自分でシナリオを作る

```bash
python3 scenario_builder.py my_scenario.json
```

質問に答えるだけで（グリッドの大きさ、壁の位置、ロボットの台数・
スタート地点・目標地点）、オリジナルのシナリオを作れます。
作ったシナリオを使うには：

```bash
python3 video_export.py --scenario my_scenario.json 出力名.mp4
python3 main.py --scenario my_scenario.json
```

Pythonのコードを直接編集したい場合は `scenario.py` を参考にしてください
（`build_default_scenario()` を書き換えるだけです）。

## アルゴリズムについて

このデモは、論文

> Crepin Simon Franck & Shohei Yokoyama, *A Distributed Multi-Meta
> Agent MTTDS Solver*, Tokyo Metropolitan University

で提案されている **DbVNS**（Decomposition-based Variable Neighborhood
Search、Algorithm 1）を、**改変せずにそのまま**使っています。

論文のDbVNSは、観光地の周遊ルート（POI＝興味地点を訪れて報酬を最大化
する問題）を解くために作られたものです：貪欲に次のPOIへ進み、行き
詰まったら **Shake**（少し後退する）→ **Decompose**（後退した地点
から選択肢を1つ禁止して枝を作る）→ **上限フィルタ**（見込みのない
枝を捨てる）→ **貪欲構築**（残った枝を伸ばす）を繰り返します。

このデモでは、これをそのまま使い、近傍候補を数え上げる箇所
（論文の `memory.check_neighborhood` に相当する部分）に、
**「この時刻にこの場所へ移動してよいか？」** という制約を1つだけ
追加しています。これは、すでにアルゴリズムが持っている「禁止された
POI（forbidden）」の仕組みに、時空間の占有情報を足しているだけで、
MAPF専用の別アルゴリズムを新たに組んでいるわけではありません。
制約を追加するだけで、探索結果は自動的に「他のロボットと衝突しない」
という意味でより現実的（＝最適）になります。

パラメータも論文の実験設定（セクション6.2.2）に忠実にしています：
`k_max = 4`、反復回数 = 100、連続空振り上限 = 3、
δ（max_divergence） = 0.3、`max_decompositions = 5`。

### 優先度つきの計画（Priority Planning）

ロボットは `scenario.py` のリストの順番（＝優先度）で、1台ずつ
順番に計画されます。先に計画されたロボットの経路は「予約」として
確定し、後から計画されるロボットは、その予約を制約として自動的に
考慮します（`reservation.py`）。

### DbVNSの限界について（正直に見せる）

論文自身が示している通り（6.3.1節）、DbVNSは必ずしも最適解を見つける
とは限りません。今回のデモでも、反復回数の予算内に目標へたどり着け
なかった場合は、無理に別の完全探索アルゴリズムに頼らず、**それまでに
見つかった最善の部分経路をそのまま採用**します。これはむしろ良い
教材になります：「ヒューリスティックな手法は万能ではない」という
ことを、生徒に実感してもらえます。

## ファイル構成

- `grid_world.py` — グリッド環境（BFSによる距離マップは論文の
  Global Memory に相当）
- `reservation.py` — 時空間の予約テーブル（衝突を防ぐ制約そのもの）
- `robots.py` — ロボットと目標地点の定義
- `scenario.py` — **デフォルトシナリオ**（各ロボット5地点、分散配置）
- `scenario_builder.py` — 対話式シナリオ作成ツール（JSON形式で保存）
- `dbvns_planner.py` — アルゴリズム本体（論文のDbVNS＋制約1つ）
- `video_export.py` — **MP4動画の生成**（メインの成果物）
- `gui.py` / `main.py` — Tkinter による対話的なGUI
- `test_headless.py` — 画面なしで衝突・到達を確認するテスト
